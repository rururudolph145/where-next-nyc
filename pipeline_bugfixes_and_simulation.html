1. Bug Fix: Ingestion — Mixed-Type Column Failure

BUG   ArrowTypeError: Expected bytes, got a 'float' object when writing Bronze parquet.

Root Cause

Raw parquet files from different months stored the congestion_surcharge column with inconsistent types — some files used float64, others used bytes. After pd.concat(), the column became object dtype containing a mix of floats and bytes. PyArrow could not serialize this mixed column to parquet.

The existing _enforce_schema() method called pd.to_numeric(df[col], errors="coerce"), but pd.to_numeric cannot parse raw bytes objects — it leaves them unconverted, so the column remained object dtype.

Fix

FIX   File: src/ingestion/ingest.py → _enforce_schema()

Before calling pd.to_numeric, decode any bytes values to strings:

# Before fix:
df[col] = pd.to_numeric(df[col], errors="coerce").astype(np.dtype(dtype))

# After fix:
if df[col].dtype == object:
    df[col] = df[col].map(
        lambda v: v.decode() if isinstance(v, bytes) else v
    )
df[col] = pd.to_numeric(df[col], errors="coerce").astype(np.dtype(dtype))

The .decode() converts bytes → str, which pd.to_numeric can then parse into floats. Non-bytes values pass through unchanged.

2. Bug Fix: Feature Engineering — Column Name Mismatch

BUG   KeyError: 'pulocationid' during groupby in build_hourly_demand().

Root Cause

The Bronze schema in config.yml defines columns in mixed case (e.g. PULocationID). The Silver layer preserves these names. However, the feature engineering module expected lowercase column names (pulocationid) throughout its methods.

LayerColumn Name
Bronze / SilverPULocationID
Feature Engineering (expected)pulocationid

Fix

FIX   File: src/ingestion/feature.py → run()

Normalize all column names to lowercase at the start of the feature engineering pipeline:

# Added at the top of FeatureEngineer.run():
data.columns = pd.Index([c.lower() for c in data.columns])

This ensures all downstream methods (build_hourly_demand, add_lag_features, add_zone_coordinates) consistently reference lowercase column names without needing changes to every method signature.

3. Hourly Demand Simulation

What It Does

The HourlySimulator replays historical data hour-by-hour to simulate real-time inference. It steps through a configured time window (e.g. March 1–2, 2021), predicts taxi demand for every zone at every hour, and compares predictions against actual trip counts.

Pipeline Flow

01 Ingest
Raw → Bronze → 02 Clean
Bronze → Silver → 03 Feature
Silver → Gold → 04 Train
Gold → Model → 06 Simulate
Model + Gold → Predictions

How It Works

# Pseudocode for HourlySimulator.run()

model = load("models/model.pkl")
gold  = load("data/gold/.../hourly_demand_featured.parquet")

# Filter to the simulation window (config.inference.simulation)
sim_df = gold[ start_hour ≤ hour ≤ end_hour ]

for each hour_ts in sim_df.unique_hours:
    # Get all zones for this hour
    hour_slice = sim_df[hour == hour_ts]

    # Features: cyclical time encodings, lat/lon, lag counts
    X = hour_slice[feature_columns]

    # Predict demand for every zone at this hour
    predictions = model.predict(X)

    # Record (zone, hour, predicted, actual) for evaluation
    records.append(zone_id, hour_ts, predicted, actual)
