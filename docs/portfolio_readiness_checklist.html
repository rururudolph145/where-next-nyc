Top 5 Highest-Leverage Fixes Do First

Ranked by impact-per-hour. Completing these alone moves the repo into A− territory.

  • 1. Add a real CI workflow
    Create .github/workflows/ci.yml running pytest, ruff, and mypy on every PR. Today the only workflow is a docs deploy. A senior reviewer checks for this first.
    ~1–2h
  • 2. Implement a naive baseline + publish a comparison table
    Add a last-week-same-hour or seasonal-naive baseline; publish baseline-vs-LGBM MAE/RMSE/WAPE in the README. Without this, your model's lift is unproven — the #1 question a senior MLE will ask.
    ~2–3h
  • 3. Write a working Dockerfile for the FastAPI app
    README already promises docker build -t ny-taxi-demand ., but no Dockerfile exists in the repo root. Fulfilling this turns the project from "looks serious" into "runnable in one command".
    ~1h
  • 4. Extract duplicated evaluate() into app/core/metrics.py
    The identical metric function is copy-pasted across trainer.py, predictor.py, and simulator.py. Centralize it. Visible DRY win.
    ~30m
  • 5. Add data-download script + embed results & heatmap in README
    Create scripts/download_data.sh for TLC parquets and the taxi-zones shapefile. Embed sample_heatmap.png (currently untracked) and an eval-metrics table in the README so readers see proof the model works.
    ~1–2h

B. ML Craft MLE Bar

Signals an MLE interviewer probes for after the first 5 minutes.

  • Add a naive baseline (covered in Top 5)
    Last-week-same-hour, historical mean by (zone, hour-of-week). Quantify LGBM's lift over baseline.
    Missing
  • Replace single hold-out with walk-forward CV
    For a 3-month dataset a single split gives one evaluation point. Walk-forward / expanding-window evaluation across multiple folds is what MLEs expect for time series.
    Weak
  • Log richer MLflow artifacts
    Currently logs params, metrics, model. Add: feature importance plot, residual distribution, per-zone error heatmap, the config.yml snapshot.
    Partial
  • Implement MLflow model registry + stage management
    Replace joblib.dump(model.pkl) with mlflow.register_model(). Manage Staging → Production → Archived. Required by your own reference design.
    Missing
  • Add validation gate before promotion
    In Trainer.run(), reject models whose val MAE/WAPE is worse than current champion or a fixed threshold. Today every trained model is silently promoted.
    Missing
  • Implement fallback to previous approved model
    If new model is rejected, simulator/API should continue serving the previously approved model. Reference design explicitly calls this out.
    Missing
  • Add drift monitoring (Evidently) — PBIs 23 + 24
    PBI 22 has shipped the prediction log + actuals join (the data foundation). PBI 23 adds app/monitoring/drift.py (Evidently DataDriftPreset + RegressionPreset over the joined frame); PBI 24 adds alert.py that emits a retrain_required marker. PBI 25d then wires those into the monitor_hourly_dag with a FileSensor hand-off to the training DAG.
    Missing
  • Per-zone / per-hour error analysis notebook
    Commit a rendered notebook showing where the model fails (e.g., airport zones at midnight, special events). Demonstrates ML maturity.
    Missing

C. MLOps / Systems Differentiator

Where MLE candidates either separate themselves or blend in.

  • Write a real Dockerfile (covered in Top 5)

    Missing
  • Add docker-compose.yml for the serving stack
    API + MLflow + (optional) MinIO/Postgres. Lets reviewers run the full system in one command.
    Missing
  • Promote Airflow DAGs out of experiment/ (PBIs 25a–25d)
    The 15-min orchestration is currently under experiment/orchestration/, signaling "not production". The work is sequenced as four PBIs: 25a moves the directory to orchestration/ and adds the Clock abstraction (foundation, no DAGs); 25b ships refresh_15min_dag (ingestion → inference cadence); 25c ships train_monthly_dag (training + PBI 20 registry gate); 25d ships monitor_hourly_dag (drift → retrain feedback loop, after PBIs 23 + 24). 25b and 25c are independently shippable in parallel once 25a lands.

    Pipeline is a sequential Python script. refresh_15min_dag in PBI 25b owns the (date, bucket) watermark contract — rerunning the same bucket is a no-op, and airflow dags backfill covers historical reruns. Each ingestion stage becomes write-once under that watermark.
