Top 5 Role-Aligned Fixes Do First

Ranked by impact-per-hour against the two target JDs. Completing these moves both grades to A−.

  • 1. Ship PBI 25a — Clock abstraction + orchestration/ skeleton
    Unblocks the entire demo story: WallClock vs. SimulatedClock, repo-wide grep regression test, DEMO_MODE=1 selection at startup. The README already promises this. Without it, "Airflow orchestration" stays in experiment/ and reviewers see a half-built claim.
    Role fit: Google "robust, scalable software systems"; SmartNews "production ML workflows" — a clean clock abstraction is exactly the kind of testability move senior reviewers reward.
    ~6–8h
  • 2. Write the Dockerfile + add it to CI
    README promises docker build -t ny-taxi-demand . — no Dockerfile exists. Multi-stage build, slim Python base, non-root user, uvicorn entrypoint. Add .github/workflows/docker.yml that builds on PR and pushes to ghcr.io on tag pushes. Highest visibility-per-hour for a SWE reviewer.
    Role fit: Google "scalable software systems" / SmartNews "model deployment".
    ~1–2h
  • 3. Ship PBI 28 — Driver-agent simulation harness
    Three policies (HeatmapFollower, LastWeekFollower, Stationary) replay a held-out TLC week and report per-policy trips served, idle %, miles-to-pickup, total fare. This is the only way to turn "the model is accurate" into "drivers following the model are better off" — and it's also a working A/B-test framework on synthetic data.
    Role fit: SmartNews "experimentation: hypothesis → offline eval → A/B → online" (this is the offline arm); Google "design and run experiments to refine valuation models".
    ~6–10h
  • 4. Ship PBI 29 — Latency SLO baseline + CI guard
    Benchmark /heatmap P50/P95 under load; commit the numbers; add a CI regression test that fails the build if P95 exceeds the baseline by >X%. The README claims "Sub-200ms response from precomputed cache" — make that verifiable, not aspirational. Pairs naturally with PBI 30's CI infrastructure.
    Role fit: Google "scalable software systems, engineering best practices" / SmartNews "online serving".
    ~3–4h
  • 5. Add a "Signals & Evaluation" notebook (per-zone / per-hour error analysis)
    Commit a rendered notebook that segments WAPE/recall@K by zone and hour-of-day, surfaces where the model fails (airports at midnight, special events), and proposes which signal would close each gap. This is the single most-undervalued portfolio asset for senior reviewers — it demonstrates ML maturity beyond "I can fit a LightGBM".
    Role fit: Google "analyze datasets to understand attributes that contribute to quality"; SmartNews "user behavior analysis, diagnose performance gaps".
    ~2–3h
