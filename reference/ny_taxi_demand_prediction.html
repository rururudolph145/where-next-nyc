Five-lane ML architecture for the NYC taxi demand heatmap. Three pipelines (ingestion, training, inference) sit between a top-of-stack orchestrator that drives every refresh and a bottom-of-stack monitoring lane that closes the feedback loop on data drift, model drift, and actuals.

Retrain Trigger fires orchestrator
Closes the loop — without this lane, the validation gate and fallback are blind: no one knows when the current champion has degraded. Drift & performance signals are what trigger a retrain (top-of-stack DAG) and what give the gate a meaningful baseline to compare against.

C00 · Orchestrator

Airflow

  • Owns refresh cadence (15 min + monthly)
  • Schedules ingestion, training, inference
  • Reacts to drift alerts (retrain triggers)
  • Enforces idempotency & backfill semantics
  • Single source of truth for "when"

C01 – C03

Data Ingestion & Prep

  • Ingests raw NYC taxi trip records
  • Validates schema + quality (drift gate)
  • Computes time/geo + lag features
  • Generates train-ready datasets
  • Publishes online features to feature store

C04 · Monthly + on-drift

Training Pipeline

  • Trains model on latest dataset
  • Validates against held-out data + champion
  • Gates deployment on metrics
  • Registers versioned model artifact
  • Fallback: serves previous approved model

COS · 15-min refresh

Inference Pipeline

  • Loads champion model from registry
  • Reads fresh features from feature store
  • Serves /heatmap to driver apps
  • Returns ranked zones with coordinates
  • Sub-200ms response from precomputed cache

C05 · Continuous

Monitoring & Feedback

  • Logs every served prediction
  • Joins actuals once trips materialise
  • Detects data drift + model performance decay
  • Fires retrain trigger to orchestrator
  • Surfaces alerts for on-call review
